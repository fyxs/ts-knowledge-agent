# TS Knowledge Agent：V1 设计

## 1. 定位

面向小型团队的本地化 Agent 知识处理应用。成员按自己的习惯在本机提供和分类原始材料；应用负责发现、读取、转换、整理、沉淀和搜索。第一期的核心是知识生产与搜索服务，不是执行型 Agent，也不是 Claude Code/Hermes 的替代品。

## 2. V1 范围

```text
本地知识源目录
  → 文件扫描与变化识别
  → MarkItDown 转换
  → Markdown/元数据整理
  → 写入固定 Git 知识仓的成员空间
  → 本地全文搜索
```

第一期支持单公司场景；不配置公司范围和项目范围。项目、制度、模板、演讲等关系由源文件目录和内容自然表达。

## 3. 固定约束

- 知识仓固定为 `git@github.com:fyxs/ts-knowledge-base.git`，不在普通初始化流程中开放切换。
- 每个成员初始化时必须配置 `member_id` 和自己的个人空间。
- 成员空间用于区分写入归属、维护责任和避免协作污染；进入知识仓的内容默认团队共享，Agent 默认可检索全部成员空间。
- 原始文件所在位置就是原始源。应用只能扫描、读取、转换、提炼、登记和搜索，不移动、归档、覆盖、重命名或删除源文件。
- CLI 采用自带独立运行环境；MarkItDown 等转换能力由应用集成或管理，不要求成员手工安装。
- 模型调用第一期沿用当前工作模型/Harness 配置；应用不绑定具体模型供应商，也不把模型配置写入知识仓。
- 本项目只存应用代码；`ts-knowledge-base` 只存共享知识、来源登记、规则和知识技能。

## 4. 本地运行组件

```text
CLI
  ├── init：配置 member_id、源目录和本地运行参数
  ├── scan：确定性扫描文件和哈希
  ├── convert：调用内置 MarkItDown
  ├── extract：调用工作模型生成候选知识
  ├── index：建立/更新本地全文索引
  ├── search：搜索共享知识和转换材料
  └── status：显示处理状态和错误

本地服务
  ├── SQLite：本机扫描、任务、转换和索引状态
  ├── Git 工作区：ts-knowledge-base 的本地副本
  └── Web 搜索界面：第一期可选，复用同一核心服务
```

SQLite 不跨成员共享、不提交 Git；团队共享通过 Git 知识仓完成。

## 5. 知识生命周期

```text
discovered → converted → extracted → candidate → verified
                                ↘ failed
source_missing 仅表示源文件被用户删除或不可访问
```

MarkItDown 输出是可分析材料，不等于已验证知识。原始文件必须保留，转换结果记录来源路径、哈希、转换时间和工具版本。知识条目必须回指原始文件和转换材料。

## 6. 外部 Agent 接入边界

第一期不实现 Claude Code、Hermes 等外部 Agent 的 MCP、子 Agent、HTTP 或自动上下文注入。接口设计留在后续阶段：未来由本项目提供只读知识服务，外部 Agent 显式调用，获取带来源、状态和不确定项的知识上下文。

外部 Agent 接入不是知识仓库自动发现机制；不能依赖 `ts-knowledge-base` 内的 `CLAUDE.md` 或 `skills/` 被自动读取。

## 7. V1 完成标准

- 能配置成员个人空间和一个本地源目录；
- 能扫描新增/修改/删除状态而不改变源文件；
- 能将支持的文件转换为 Markdown；
- 能把处理结果和知识写入成员空间；
- 能通过 Git 同步团队知识；
- 能在本地搜索整个团队知识仓；
- 搜索结果带来源和知识状态；
- 记录错误、重试和完成结果；
- 不把原始敏感文件、凭据或 SQLite 提交到知识仓。
