# TS Knowledge Agent：V1 细节设计

## 1. 定位

面向 TS 小型团队的本地化 Agent-first 知识处理应用。成员按自己的习惯在本机提供和分类原始材料；应用负责发现、读取、转换、整理、沉淀和搜索。第一期核心是知识生产与搜索服务，不是执行型 Agent，也不是 Claude Code/Hermes 的替代品。

## 2. 一期范围与边界

```text
本地知识源目录
  → 每小时扫描
  → 变化识别与任务排队
  → MarkItDown 转换
  → Markdown/元数据整理
  → 写入固定 Git 知识仓成员空间
  → 本地全文索引
  → 每小时批次同步到 GitHub
```

一期只处理本地知识源，不接入飞书、网盘、邮件等线上数据；单公司场景，不配置公司/项目范围。

固定仓库：`git@github.com:fyxs/ts-knowledge-base.git`。应用源码独立位于 `ts-knowledge-agent`，不写入知识仓。

## 3. 成员空间与共享

每台成员机器初始化时必须配置 `member_id` 和个人知识空间。知识仓使用：

```text
members/<member_id>/
├── materials/
├── converted/
├── knowledge/
├── projects/
└── reviews/
```

成员空间只用于区分写入归属、维护责任和避免互相覆盖；进入固定知识仓的内容默认团队共享，所有成员 Agent 都可调用。不存在 `shared/` 作为额外可见性分区。

## 4. 源目录扫描

### 4.1 每小时任务（一期主机制）

每小时执行一次完整一致性扫描，默认扫描成员初始化配置的本地源目录，例如 `D:/2Work/Knowledge/TS`。扫描只读取，不改变源文件。

扫描记录：路径、文件名、扩展名、大小、修改时间、SHA-256、首次发现、最后发现和处理状态。

扫描识别：新增、内容修改、路径变化、源文件缺失。仅当路径、大小、mtime 或哈希发生变化时产生处理任务。

### 4.2 实时监听（后置能力）

一期不依赖实时监听。未来可增加 watchdog 作为及时触发器，但每小时完整扫描仍保留，作为监听丢事件、应用停止和批量复制的兜底。

## 5. 转换与沉淀

用户先按自己的习惯分类和放置材料；系统只处理配置范围内被发现的文件。文件稳定后调用 CLI 内置或管理的 MarkItDown，原文件不移动、不覆盖、不重命名、不归档、不删除。

转换结果写入当前成员空间的 `converted/`，不得覆盖已有不同版本；记录转换器版本、参数、源文件哈希和质量标记。MarkItDown 输出只是可分析材料，不是已验证知识。

Agent/工作模型沿用当前 Harness 工作模型配置，用于摘要、分类、知识抽取和候选关系整理；确定性扫描、哈希、转换调用、索引和 Git 操作由程序完成。

## 6. 每小时 Git 同步

每小时处理任务完成后，执行同步阶段：

```text
git fetch/pull
  → 检查工作区和合并冲突
  → 汇总本小时变更
  → 质量与敏感信息检查
  → commit
  → push 固定 origin/main
  → 回读远程 SHA
```

正常的小批量新增、修改和成员空间删除可以自动同步。同步批次应包含清晰摘要，例如 `ingest: hourly knowledge update for <member_id>`。

以下情况暂停 push 并记录：Git 冲突、异常大量删除、输出为空或异常缩短、疑似敏感信息、Schema 或 Agent 规则被改动、转换或提炼失败。

## 7. 删除与源文件生命周期

### 7.1 用户删除本地原始源

检测到源文件缺失时标记 `source_missing`，不删除转换 Markdown、知识条目或 Git 历史；搜索结果提示源文件当前不可重新验证。是否删除派生知识由用户另行决定。

### 7.2 用户删除成员空间中的 Markdown

检测到 `members/<member_id>/` 内文件被删除时：

1. 更新本地索引；
2. 记录删除对象、关联 source_id 和删除时间；
3. 将 Git 删除纳入当前小时批次；
4. 正常情况下自动 commit/push。

若删除数量异常、涉及非当前成员空间、被其他知识引用或涉及共享规则，暂停 push，等待确认。Git 当前版本删除但历史版本仍可追溯。

## 8. 本地 SQLite 与日志

SQLite 只保存在成员本机，记录文件清单、哈希、任务状态、转换映射和全文索引；不进入 Git，不在成员间共享。

需要日志，但一期不部署独立日志平台：

```text
本地 logs/app.jsonl：运行事件、耗时、错误
SQLite：任务状态、哈希、重试、删除和索引状态
Git：共享知识内容变更历史
```

日志不得记录正文、Token、密码、Cookie 或完整模型请求。

## 9. V1 完成标准

- CLI 初始化可配置 `member_id`、个人空间和本地源目录；
- 每小时扫描能识别新增、修改、路径变化和缺失；
- 能调用内置 MarkItDown 转换支持的文件；
- 原始文件始终不被修改；
- 结果写入当前成员空间；
- 每小时按批次同步固定 Git 仓；
- 能检测成员空间 Markdown 删除并同步；
- 本地全文搜索可搜索整个团队知识仓；
- 结果包含来源和状态；
- 异常变更可暂停自动推送；
- 本地 SQLite、日志和敏感信息不进入知识仓。

## 10. 后置能力

实时监听、向量检索、知识图谱、Web Agent 问答、MCP 只读服务，以及 Claude Code/Hermes 等外部 Agent 接入均后置。
